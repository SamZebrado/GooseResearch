# AI执行效率检查

状态：尝试中。这里记录一种正在尝试的回顾方法，不是已经验证有效的通用标准，也不是可直接接入项目的自动检查产品。

## 想解决什么

AI 辅助工作有时会不断汇报、核对和等待，却难以看出整体目标推进了多少。这份检查从实际产出和完成证据出发，辨认必要的验证、真正的阻碍，以及可以减少的重复周转。

目标是让重要工作继续推进，并尽快收尾小问题。不是为了减少检查而跳过必要的安全、权限、质量或人工决定。

## 每次回顾的六个问题

1. **整体目标是什么？** 用一句话写清期望交付，区分必须完成、可以后补和暂时不做的内容。
2. **实际完成了什么？** 看产物、运行结果、检查记录和人的决定。已收到请求、已安排工作、命令成功退出，分别不等于已完成或已验收。
3. **真正卡在哪里？** 写出缺少的输入、决定或证据，以及缺它会影响什么。缺乏证据先标为未知，不直接当作失败。
4. **有没有重复周转？** 区分有新证据的复核和对同一状态的重复盘点。一次列明验收需要的材料，减少每交一份又发现下一份缺口。
5. **什么可以并行或先收尾？** 独立工作不必等待所有任务结束；先检查依赖与是否已有工作在途，避免重复提交。小问题若不影响当前交付，可记录后续处理，但不能掩盖必要条件仍未满足。
6. **下一步是什么？** 指定一个具体动作、负责方、预期产物和完成依据。需要用户决定时，说明决策影响，而不是把整份状态再转述一次。

## 一个完全虚构的例子

假设正在做一个公开示例“植物浇水小助手”。目标是展示提醒逻辑；示例没有真实用户或私人项目来源。

- 已完成：提醒列表能显示，基础测试通过。
- 尚未核实：关闭页面后重新打开，设置是否保留。
- 可避免的周转：反复确认首页已经显示，却没有检查设置保存。
- 可独立推进：在测试保存功能时，另行整理公开使用说明。
- 可以后补：不影响操作的装饰图标。
- 下一步：验证保存与重新打开的流程，记录通过、失败或未执行。若保存失败，修复后重跑相关测试，不把截图当成这项行为的证据。

这只是说明检查方式，不是实际项目进展或效果统计。

## 简短记录模板

- 整体目标与当前阶段：
- 新完成的产物及证据：
- 阻碍与不确定性：
- 必要验证 / 可减少的重复周转：
- 可并行或先收尾的事项：
- 下一动作及完成依据：

没有新证据时，不用为了填满模板发明进展。检查本身也应有界，不能成为新的排队环节。

## 正在尝试：三省六部协作审议

更新：2026-11-11。将原先的三部视角示例整理为[三省六部特化 Skill](../skills/three-provinces-six-ministries/SKILL.md)。这是按需选用的实验流程，不是所有任务的新审批门槛，也不要求固定六个 agent 或声称经过六次独立验证。

### 六部分工

- **兵部：** 后续计划、接续路径、依赖与可并行工作，并复核提示词对后续的影响。
- **户部：** 预算与资源，兼顾计算、排队、协调和反复试探成本；给足合理资源，不刻意追求绝对最小，不扩大既有授权。
- **工部：** 输入、工序、依赖、可执行性和验收；分析异常、提出可行修正，并复核最终提示词。
- **吏部：** 核对六部与协调者、主负责人、其他 agent 的分工、负责范围及交接，检查遗漏、重叠、越位和在途冲突；不只管六部内部。
- **礼部：** 检查通俗易懂、对象、术语和证据，清除空泛套话等“AI味儿”；退回模糊意见，再作可执行概括，不冒充 AI 作者鉴定。
- **刑部：** 监督真实性、核查范围和对外表述，记录自查与纠错并跟踪改正；不新增审批或处罚权。

中书省召集必要六部代表起草，门下省召集必要代表审核并可退回中书，尚书省决定向哪些 agent 发哪些完整提示词。尚书下的将军能分析、画图并管理获准计算平台；宰相有轻量资源，可画总结图、改已有图和统筹决策，但不能做数据分析，也不越过三省审核调度。保留“宰相”名称，不把其视为三省上级。名称是协作意象，不是历史官制复原。

翰林院按需核对明确给定的作者或其他写作参照及已有习惯；没有来源不猜测，不属于六部，也不增加审核调度权。礼部负责讲得清楚，翰林院负责是否符合指定参照，职责不同。

可先看[独立演示页](../skills/three-provinces-six-ministries.html)，再读完整规范。

后宫是独立支持角色，可用非暴力沟通及 CBT 相关方法提供经用户认可的支持。明显情绪波动时只提议；认可后才分析，不认可就停止，不诊断或代替治疗，不参与或指挥执行。工作及对外沟通中的非暴力沟通归礼部。

大内总管负责生活习惯与起居照料，根据有依据的情况温和提醒，不指责、不诊断，不把未记录视为没做。御史核工作习惯，例如提示词阅读中的实际误解；用原文与具体差异提醒，不把未回复视为未读，不以不同意见推定不认真。二者不凭提醒擅自改派或替用户作决定。

### 显式顺序与迭代

**兵部列可能后续计划 → 户部、工部先发表意见 → 吏部判断分工 → 礼部概括 → 发提示词 → 工部和兵部复核 → 必要时修订；意见复杂时，从户部、工部再来一轮。**

每一步给用户可见的简短判断与依据，不只内部检查后交总意见。“发提示词”首先是交给用户一份完整、自包含、标版本的文本，不意味着已向执行者发送。实际发送仍要符合具体授权。中书负责起草，门下组织工部和兵部复核刚才交出的准确版本，可退回中书；通过后尚书才决定实际分派。需要修改就给完整新版，不让用户自己拼接。已发版本只要求评估时，不自动重发。

刑部贯穿事实和纠错检查，不另插固定审批阶段。复杂分歧带新增证据回到户工，随后继续分工、概括和复核；没有新证据时不循环复述。结论、职责、验收和授权齐备便收束，继续已授权工作，不让局部问题拖住独立部分。

### 怎样判断是否有帮助

检查下一动作是否真正执行、是否减少无根据的停顿，同时记录重复提交、越界、返工或阅读负担。没有比较证据就不宣称效率收益。可用[外星人研究完整示例](../skills/three-provinces-six-ministries/references/fictional-handoff.md)查看各部具体回复，判断将军负责数据分析还是宰相可直接画图，以及完整提示词、复核、修订与模拟执行闭环。它不是实际项目回执。

保留对管理学经验和外部方法的辨证判断：区分来源证据、适用情境与副作用。公开或流行不代表已验证有效，也不能替代本任务实际证据。

## 其他人是怎么做的

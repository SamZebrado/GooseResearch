讨论 → 提纯 → 网页审核 → 导出迭代

这是一个通用 Skill 的实验设想与公开规格，不是已完成跨平台验证的产品。普通 AI 用户也可以把它当作对话工作流，不需要先会安装 Skill。

先讨论，不急着生成

告诉 AI 想解决什么、哪些是原文、哪些只是问题、什么不能改。让它先区分“解释一下”和“修改正文”，再保留出处提纯反馈。

两种模式并列

Systematic：系统理解与逐步修订
To-do：只审核当前反馈

可以先系统理解，再处理待办，也可以只用其中一种。看过不等于同意；助手待办不要伪装成读者作业。

导出后继续讨论

网页支持导出时，将反馈、来源版本与选择保留成文件，检查隐私后自行交回 AI，生成带差异说明的候选新版。没有文件能力时，用结构化文字复制也可以。不同平台的文件、网页、存储和权限能力需要分别验证。

普通聊天可用的起手式

先与我讨论目标，再整理我提供的材料。保留原话和出处，把只需解释与需要修改分开。需要系统理解时给我 Systematic 视图；只想处理新反馈时给我独立 To-do 序列。不要把看过当批准，不要替我公开材料。最后说明如何导出或复制反馈继续迭代。

特化例子：三省六部协作审议

中书起草，门下审核并可退回，尚书决定给哪些 agent 发什么。需要显式核对多 agent 分工和完整交接时，可使用独立的三省六部流程：兵部计划 → 户工意见 → 吏部分工 → 礼部概括 → 完整提示词 → 工兵复核 → 必要修订。复杂意见从户工回环；给用户提示词不等于发送给执行者。

打开三省六部独立 demo · 阅读特化 SKILL.md · 外星人研究：各部回复与执行示例

仍是实验规格，不自动安装或发送；普通反馈整理不必采用这套流程。

验证边界

公开 demo 已有独立浏览器检查；这不代表 Skill 已经在不同 AI 产品中安装或通过端到端验证。Skill 本次是按结构整理的工作流规格，没有自动安装到个人账户，也没有自动调用模型、上传或发布用户材料。

所有示例独立虚构，不包含真实项目内容。现有 To-do demo 只演示已看、筛选、原文对照和撤销/重置；导出闭环是工作流要求，不冒称该 demo 已实现完整导入导出。
